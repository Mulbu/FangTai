# 方太个性化膳食规划 Agent · 部署文档

## 1. 系统概览

基于大语言模型（GLM-5.3-flash）+ GPU 混合检索（BM25 + bge 向量 + bge 重排）的个性化健康膳食推荐系统。

- **后端**：FastAPI（SSE 流式），Python 3.10+
- **RAG**：sentence-transformers（CUDA GPU 推理），索引离线预计算
- **LLM**：OpenAI 兼容协议（默认智谱 glm-5.3-flash，思考强度可调）
- **前端**：内置 Web 聊天界面（`/`）

## 2. Docker 部署（推荐，评测环境）

前置要求：NVIDIA 显卡 + NVIDIA Container Toolkit + Docker Compose v2。

全部配置集中在 `docker-compose.yml`（无 .env 文件）。按评测机显存选择档位：

```bash
# A100 80G 档：bge-m3(1024维) + bge-reranker-v2-m3
docker compose --profile a100-80g up -d --build

# A100 12G 档（或本地开发机任意显卡）：bge-large-zh-v1.5 + 轻量重排
docker compose --profile a100-12g up -d --build
```

- 服务地址：`http://<host>:8000`，Web 界面在根路径
- 首次启动会自动下载嵌入/重排模型并构建向量索引（GPU 约 1-3 分钟），
  已挂载 volume 缓存，后续启动秒级就绪
- 健康检查：`curl http://127.0.0.1:8000/api/health`

### 关键配置项（docker-compose environment 段）

| 变量 | 说明 | 默认 |
|---|---|---|
| LLM_BASE_URL | OpenAI 兼容端点 | 智谱 paas/v4 |
| LLM_API_KEY | API 密钥 | （compose 中已填） |
| LLM_MODEL | 主模型（方案说明生成） | glm-5.3-flash |
| LLM_FAST_MODEL | 轻任务模型（槽位抽取/选菜） | glm-5.3-flash |
| LLM_THINKING | 思考强度 disabled/low/**high**/max | high（质量优先） |
| EMBEDDING_MODEL | 嵌入模型（GPU） | 按档位 bge-m3 / bge-large-zh |
| RERANKER_MODEL | 重排模型（GPU），空串禁用 | 按档位 |
| EMBEDDING_DEVICE | auto=自动检测 CUDA | auto |
| HF_ENDPOINT | 模型下载镜像 | hf-mirror.com（无外网环境可挂载离线模型后移除） |

评测环境无外网时：将 huggingface 模型目录挂载进容器并在 compose 中去掉 HF_ENDPOINT，
或提前在有网机器 `docker pull` 好镜像、用 volume 复用模型缓存卷。

## 3. 本地开发运行（Windows/Linux）

```bash
pip install -r requirements.txt   # torch 需 CUDA 版（开发机无 GPU 也可跑，自动回退 CPU/BM25）

# 环境变量（等效于 compose 的 environment 段）
set LLM_API_KEY=xxx
set LLM_MODEL=glm-5.3-flash
set LLM_THINKING=high

python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

首次启动自动构建索引；也可离线预构建：`python scripts/build_index.py`

## 4. API 一览

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /api/chat | 多轮对话，SSE 流式（intent → plan → delta* → done） |
| POST | /api/recommend | 单次推荐，JSON 返回（便于程序集成/评测） |
| GET | /api/recipes?q=&limit=&offset= | 菜谱库检索 |
| GET | /api/recipes/{id} | 菜谱详情（含结构化食材/标签/分类） |
| GET | /api/profiles?kind=detailed\|simple | 50 份健康档案 |
| GET | /api/sessions/{sid} | 会话状态（约束栈/当前方案，可审查多轮一致性） |
| GET | /api/health | 健康检查（GPU/索引状态） |

### /api/chat 请求

```json
{"message": "今晚吃啥比较好？", "session_id": null, "profile_ids": [3], "reset": false}
```

`profile_ids` 支持多选（多人宴请场景，约束自动取交集）。响应头 `X-Session-Id` 返回会话号，
后续轮次带上即可延续上下文。SSE 事件：

```jsonc
{"type":"intent","slots":{...}}                      // 本轮槽位理解
{"type":"plan","dishes":[...],"nutrition_per_person":{...},"constraints_applied":"..."}  // 结构化方案（机器可校验）
{"type":"delta","text":"..."}                        // 正文流式增量
{"type":"clarify","question":"..."}                  // 模糊需求主动澄清
{"type":"done","stats":{"first_event_s":..,"total_s":..}}
```

## 5. 评测与测试

```bash
python scripts/eval.py --api http://127.0.0.1:8000   # 20 组对话用例全量评测
python scripts/eval.py --api http://127.0.0.1:8000 --case 20   # 单用例
python tests/test_core.py                            # 核心模块单元测试
```

评测输出（eval_report.json）含：首 Token 延迟 / 单轮端到端 / 多轮平均 / 过敏违反数 /
幻觉菜名数 / 零违反通过率，并对性能指标按赛题"优秀/合格"档位评级。

## 6. 目录结构

```
app/
  main.py            FastAPI 入口（启动预热）
  config.py          配置（全部读环境变量）
  core/
    llm.py           LLM 抽象层（多 provider、流式、思考格式自动探测）
    recipe_store.py  菜谱加载清洗/食材结构化/分类
    constraint_engine.py 过敏原与疾病忌口（双遍校验）
    retriever.py     BM25+向量+重排混合检索（GPU）
    nutrition.py     营养估算 + 份额自适应
    planner.py       整桌组合优化（荤素比/多样性/按人营养）
    dialog.py        多轮状态机（约束栈/最小化修改）
    agent.py         Agent 编排（选菜零幻觉/后校验/SSE）
  api/routes.py      REST/SSE 路由
  web/index.html     Web 聊天界面
scripts/
  build_index.py     离线索引构建
  eval.py            自动评测 harness
  dev_run.py         开发调试脚本
tests/test_core.py   单元测试
data/                菜谱库 + 健康档案 + 对话用例
```
